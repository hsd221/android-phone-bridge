# Android Phone Bridge

> 基于 MCP（Model Context Protocol）协议将安卓手机能力暴露给外部 AI Agent 的桥接系统。

---

### 项目背景与初衷

Anthropic 的 Computer Use 让我们看到了大模型直接与操作系统图形界面交互的巨大潜力。用户可以让 Agent 观察屏幕、定位坐标并执行操作，从而在电脑端自主完成复杂任务。

然而在日常生活中，大量关键信息、即时通知和生活场景实际上沉淀在安卓手机中。如果能够把手机的屏幕感知与交互能力同样安全地暴露给外部 Agent，大模型就能走出电脑桌面，真正融入更多现实场景。

当前产品围绕两类按需能力提供单设备闭环：

1. **理解上下文**：读取手机端状态、屏幕内容与即时上下文；
2. **协助操作**：在用户明确授权的前提下，帮助用户在手机上完成界面查找、点击、滑动与文本输入等日常操作；

#### 核心设计考量

- **手机定位于纯粹的感知与执行工具**：  
  移动端应用不承载复杂的学习与推理逻辑，仅作为外部 Agent 的“眼睛与双手”。所有的认知、规划与决策完全交由宿主机上运行的 Agent Harness（例如 Claude Desktop 或自建系统）处理，保持移动端轻量稳定。
- **以普通未 Root 设备为基础，兼顾现实与安全性**：  
  - 基础感知和操作使用 Android 无障碍及系统权限；可选增强仅接受非 Root Shizuku 的 shell UID 2000。
  - 远端工具使用固定参数和预定义动作，覆盖 UI、手势及系统按键，不提供通用 Shell 接口。
  - Shizuku 为应用启动、本地解锁和固定输入提供受限增强；动作开始前不可用时回退无障碍，已开始的动作不会换路重放。
- **人机协同与用户最高控制权**：  
  在控制权规则上，用户始终拥有最高优先级，可随时收回控制。我们并未将“用户正在使用手机”一律作为禁止 AI 操作的硬性条件，因为现实中存在大量人机协同场景；经用户明确授权，AI 在用户使用手机期间亦可执行操作。系统通过能力与应用默认全拒绝、细粒度分权授权，以及在手机前台通知中提供即时“暂停操作”或“暂停全部访问”，确保用户对控制权拥有绝对掌控。
- **手机主动出站，适配移动网络**：  
  移动网络（Wi-Fi 与蜂窝数据）经常切换且处于运营商 NAT 之后，手机无法直接作为服务端监听入站端口。系统采用中继拓扑：手机作为客户端主动向 Bridge 建立 WebSocket 长连接，Bridge 再向上通过标准 MCP 协议对接外部系统，免去了复杂的内网穿透与公网端口监听。
- **支持自建与多用户独立部署**：  
  系统面向具备自行部署能力的用户设计，不依赖集中式的公共服务，支持任何人独立部署 Bridge 并连接自己的手机与 Agent。

### 核心能力一览

- **17 项 MCP 工具**：
  - 感知：设备状态 (`phone_status`)、设备信息 (`phone_device_info`)、应用列表 (`phone_apps`)、实时定位 (`phone_location`)、界面层级 (`phone_ui`)、屏幕截图 (`phone_screenshot`)、活动通知 (`phone_notifications`)、剪贴板 (`phone_clipboard`)、媒体元数据 (`phone_media`)
  - 操作：本地解锁 (`phone_unlock`)、启动应用 (`phone_open_app`)、点击与长按 (`phone_tap`)、手势滑动 (`phone_swipe`)、文本输入 (`phone_input`)、系统返回 (`phone_back`)、通用按键 (`phone_key`)、写入剪贴板 (`phone_set_clipboard`)
- **可选本地解锁**：
  - 单独开启后，可唤醒手机并请求系统解除锁屏，支持在手机端配置数字 PIN、文字密码或图案；
  - 锁屏凭据仅在手机本地加密保存与使用，解锁工具无参数，Bridge 和 AI 不接收凭据；
  - 未识别的系统锁屏、指纹或人脸验证交给用户；一次输入未确认成功后停止自动尝试。
- **细粒度权限控制**：
  - 默认全部拒绝，支持针对每个应用分别配置“读取”与“操作”权限；
  - “连接 / 访问 / 设置”三页导航，支持系统深色模式、大字体和即时状态刷新；
  - 提供应用搜索、批量多选授权与一键全开配置；
  - 手机端通知栏支持快捷“暂停操作”或“暂停全部访问”。
- **可靠的通信与异常处理**：
  - 支持终端二维码与手机本地扫码配对，同时保留手动输入；
  - 手机主动发起出站 WebSocket 长连接，断网自动退避重连；
  - 手机凭据基于 Android Keystore (AES-GCM) 硬件级加密保存，Bridge 端仅存储散列值；
  - 请求包含唯一 ID 与超时时间戳，超时或断网绝不重放副作用操作。
- **可选 ADB 等效增强**：启用非 Root Shizuku 后，坐标点击与长按、滑动、文本输入、返回和通用按键会先走受限的 ADB 等效输入通道；通道在输入前不可用时回退无障碍，输入后失败不会重放。`phone_key` 支持 HOME、BACK、ENTER、TAB，省略预期包名时仍检查实际前台及全部可见窗口的操作授权。应用启动和本地解锁继续使用既有 Shizuku 路径。
- **Agent 自省与视觉坐标辅助**：`phone_status.bridge` 提供运行中 Bridge 的版本、协议和工具清单，手机离线时仍可查询；截图返回 `scaleX`、`scaleY`，将截图坐标除以对应比例即可换算为物理坐标。UI 读取会继续遍历不可见容器中的可见子控件。
- **系统授权状态可见**：通知读取、图片/视频读取和 ADB 输入等独占模式会在设置页显示当前可用性；缺少授权时工具返回明确错误，不会静默绕过系统权限。

### 安装包交付

APK 通过本仓库的 [GitHub Releases](https://github.com/hsd221/android-phone-bridge/releases) 交付，发布包附带对应的 `SHA256SUMS` 校验文件。

正式版使用 `v<版本>` 标签，预发布版使用 `v<版本>-pre.<序号>` 标签并在 GitHub 标注 Pre-release。正式安装包使用非调试 Release 构建，沿用已有发布证书以支持覆盖升级。

手机端每次打开或从后台返回时自动检查新版本，包含预发布版本；发现新版后会显示下载提示。也可在“设置 → 应用更新”手动检查，点击“前往下载”在浏览器中下载对应 APK，或通过“查看发布版本”打开完整发布列表。

### 调用状态提示

在“设置 → 调用状态提示”中配置手机上的任务提示。工具调用获准后显示状态，排队调用全部完成、失败或取消后自动移除；通知仅包含工具名称与调用数量，不包含参数或返回内容。

- **实时胶囊**：默认关闭，使用 Android 标准 Live Updates。Android 16 及以上、应用通知与调用通知类别已开启，且系统允许实时更新时才可勾选；不满足条件时开关禁用并说明原因。胶囊是否展示及其外观由系统决定，通知栏保留同一条调用通知。
- **空闲时隐藏通知**：打开“隐藏空闲连接通知”，在系统页面中仅关闭“手机工具桥连接”类别，保留应用整体通知与“工具调用状态”类别。后台连接继续运行，调用期间仍能显示状态；Android 的后台运行管理入口仍可能列出本应用。
- **普通通知**：胶囊未开启或不满足条件时使用普通调用通知，同样只在调用处理中显示。通知类别可通过“工具调用通知设置”单独管理。
